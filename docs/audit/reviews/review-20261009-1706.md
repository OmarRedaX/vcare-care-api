- [ ] OPEN — Only `to` is frozen into the cursor, not `from`; a custom `from` with no `to` silently shrinks to 30 days on page 2 · `src/app/audit/window.ts:15`, `src/app/audit/service/audit.service.ts:67`
  - Scenario: `GET /api/audit-logs?from=<90 days ago>` returns page 1 over [now-90d, now) and a cursor `{t,id,to:now}`. The client follows `?cursor=...` without resending `from`; page 2 resolves `from = cursor.to - 30d`, so rows older than 30 days are never returned and `hasMore` ends early with no error.
  - Rule: spec R3/R4 ("page 2 independent of the clock", same window on every page); contract description ("later pages keep the same window").
  - Fix: freeze the effective `from` too (payload `{t,id,from,to}`, validated with the same ms pattern + `parseIsoDateTimeWithOffset`); `query.from` still wins if resent. The cursor is not shipped yet, so this is non-breaking. Update spec 3.2/R3/R4 and the contract sentence.
  - Test gap: page 1 with `from` 90 days back and `limit` small, page 2 via cursor only, assert a row 60 days old is reachable.
- [ ] OPEN — Cursor error short-circuits before the aggregated cross-field `details` · `src/app/audit/service/audit.service.ts:39`
  - Scenario: `?cursor=bad&entityId=5` returns only `{field:"cursor"}`; spec 3.1 says every cross-field problem (the table includes the cursor row) is reported together, sorted by field. `decodeSignedCursor` throws before `entityType` and the window are checked.
  - Rule: spec 3.1 cross-field validation table.
  - Fix: catch the cursor `ValidationFailed` in the service, push its detail into `details`, then continue (skip `cursor.to` for the window); throw the sorted aggregate.
  - Test gap: bad cursor + `entityId` without `entityType` + `from > to` returns three details sorted by field.
- [ ] OPEN — `decodeSignedCursor` accepts extra dot segments (`body.mac.garbage` verifies) · `src/lib/http/pagination/signed-cursor.ts:23`
  - Scenario: `const [body, mac] = cursor.split(".")` ignores a third part, so many distinct strings authenticate to the same position; breaks the "opaque, one canonical encoding" property for audit and verification cursors. Harmless for security (MAC still covers the body).
  - Rule: spec 3.2 tamper handling ("bad shape" is 400).
  - Fix: `const parts = cursor.split("."); if (parts.length !== 2) throw INVALID_CURSOR;`. Only audit and verification services call it; existing unit tests use well-formed or clearly bad cursors.
  - Test gap: `${valid}.x` is rejected in `tests/unit/lib/http/signed-cursor.test.ts`.
