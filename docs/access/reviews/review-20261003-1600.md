- [x] RESOLVED — the role check and every DDL build/execute run inside one `try`; a failure is rethrown as the fixed `Error("app_login_ddl_failed")` carrying only a SQLSTATE `code` when one matches `/^[0-9A-Z]{5}$/` — no message, no `cause`, own stack (`src/lib/knex/app-login.ts:36-43, 98-118`).   - Scenario: `trx.raw(ddl)` sends `ALTER ROLE "care_app" WITH LOGIN PASSWORD '<secret>'` as literal SQL with no bindings. On any rejection, knex `executeQuery` rewrites the message to `err.message = queryObject.sql + ' - ' + err.message` (`node_modules/knex/lib/execution/internal/query-executioner.js:38-40`); `compileSqlOnError: false` only skips binding interpolation and still prefixes the SQL.   - Test gap: a unit test where `raw(ddl)` rejects with a code-less `Error` whose message embeds the DDL. Assert that `ensureAppLogin` rejects with `app_login_ddl_failed`, and that no captured log line contains the password substring.
